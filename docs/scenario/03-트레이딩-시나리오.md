# 트레이딩 시나리오

**국면 이름 + 그때의 행동**을 정의한다. 시나리오는 가설의 소비자다 —
`02-가설-원장.md`에서 **채택된 가설만** 여기 반영하고, 각 시나리오는 자신을
정당화하는 가설 ID를 명시한다.

가설이 나중에 기각되면 그 시나리오도 함께 철회한다. **근거 없는 규칙이 코드에
남는 것을 막는 장치다.**

---

## 공통 불변식 — 어떤 시나리오에서도 깨지지 않는다

시나리오가 바꿀 수 있는 것은 **신규 진입뿐**이다.

| | |
|---|---|
| **청산은 절대 막지 않는다** | 스톱·트레일링·최대보유일은 국면과 무관하게 항상 작동한다. 위험 국면일수록 청산이 더 필요하다 — 여기서 실수하면 최악의 상황에 팔지 못한다 |
| **보유 포지션을 강제 정리하지 않는다** | 국면 악화가 곧 전량 청산은 아니다. 개별 종목 청산 규칙에 맡긴다 |
| **사람이 개입하지 않는다** | 시나리오는 게이트 파라미터를 바꿀 뿐이다. 어떤 국면에서도 개별 종목을 사람이 고르거나 거부하지 않는다 |
| **킬 스위치가 시나리오보다 위다** | 킬 스위치가 걸리면 시나리오와 무관하게 신규 진입 중단 |

구현상 이 불변식은 `core/gate.py`가 지킨다 — 게이트는 진입만 다루고 청산 항목은
그대로 통과시킨다(`00` 설계서 4.1절).

## S1 — 정상 (기본값)

| | |
|---|---|
| **상태** | ✅ 운영 중 |
| **조건** | 다른 시나리오에 해당하지 않을 때 |
| **행동** | `exposure = 1.0`. 워치리스트 순위대로 최대 5슬롯, 종목당 20% |
| **근거 가설** | 없음 (기준 상태) |

현재 이 시나리오만 존재한다. 아래는 전부 **가설 검증 후에** 활성화된다.

---

## S2 — 위험회피 *(제안, 미활성)*

| | |
|---|---|
| **상태** | 🔲 H001 검증 대기 |
| **조건** | (H001 채택 시 확정) |
| **행동** | `exposure = 0.0` — 신규 진입 중단. 보유·청산 불변 |
| **근거 가설** | H001 |

**활성화 조건**: H001이 out-of-sample까지 통과. 기각되면 이 시나리오는 폐기한다.

---

## S3 — 과열 *(제안, 미활성)*

| | |
|---|---|
| **상태** | 🔲 H003 검증 대기 |
| **조건** | (H003 채택 시 확정) |
| **행동** | `exposure` 부분 축소 (0과 1 사이) |
| **근거 가설** | H003 |

**이진이 아니라 연속값**인 이유: 임계값 근처에서 켜졌다 꺼졌다 하면 회전율이
올라가고, 현재 총거래비용비중이 이미 5.75%다. 히스테리시스를 함께 적용한다
(`00` 설계서 4.4절).

## 시나리오 전이 기록

시나리오가 활성화되면, **언제 어느 시나리오였는지**를 남긴다. 남기지 않으면
"그때 왜 안 샀나"를 사후에 재구성할 수 없고, 필터가 실제로 작동했는지 검증할
수 없다.

`CycleResult.rejections`에 `RejectReason.RISK_OFF`로 기록되므로 백테스트에서는
자동으로 남는다. 실전은 상태 전이 시 텔레그램 알림을 보낸다 — **조용히 매매를
멈추는 것이 가장 위험하다.** 봇이 안 사는 것인지 고장 난 것인지 구분되어야 한다.

## 작성 규칙

새 시나리오를 추가할 때:

1. **근거 가설 ID를 반드시 적는다.** 없으면 추가하지 않는다
2. **행동은 공통 불변식을 넘지 않는다** (진입만 조절)
3. **조건은 코드로 판정 가능해야 한다.** "시장이 불안하면" 같은 서술 금지 —
   `core/regime.py`의 순수 함수로 표현할 수 없으면 시나리오가 아니라 감상이다
4. 겹치는 시나리오는 **우선순위를 명시**한다
