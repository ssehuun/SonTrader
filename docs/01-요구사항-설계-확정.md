# 트레이딩 시스템 요구사항 · 설계 확정본 (v1.0)

---

## 1. 개요

DART/KIND 공시를 신호로, 모멘텀 팩터로 선별한 워치리스트 안에서 국내 주식을 매매하는
스윙 트레이딩 시스템. 진입은 사람 승인 후 다음 개장 시가, 청산은 완전 자동 즉시 집행.

### 1.1 핵심 설계 원칙

1. **백테스트와 실전은 동일한 전략·게이트 코드를 실행한다.**
   차이는 시계(clock)와 집행기(executor) 두 개뿐이다. 이 원칙이 깨지면 백테스트는 무의미하다.
2. **거래를 억제하는 로직이 전략만큼 중요하다.**
   자동 신호 생성 시스템은 방치하면 반드시 과매매로 간다. 게이트는 1급 컴포넌트다.
3. **상태는 복구하는 것이 아니라 재구성하는 것이다.**
   백업 시점과 장애 시점 사이의 공백은 어떤 방식으로도 남는다.

### 1.2 운용 제약

| 항목 | 값 |
|---|---|
| 초기 자본 | 1,000만원 |
| 시장 | 국내 주식 단독 (미국은 2단계 이후) |
| 최대 보유 | 5종목, 균등 20%씩 |
| 목표 현금 비중 | 없음 (신호 부족 시 자연 발생) |
| 보유 기간 | 수일 ~ 수주 (스윙) |
| 이벤트 소스 | DART / KIND 공시 (실적 공시 포함) |
| 감시 범위 | 전종목 |
| 매매 후보 | 워치리스트 상위 50종목 |
| 브로커 | KIS OpenAPI |

### 1.3 집행 비대칭

| | 타이밍 | 승인 |
|---|---|---|
| **진입** | 다음 개장 시가 | 반자동 (사람 승인) |
| **청산** | 장중 즉시 | 완전 자동 |

반자동의 목적은 잘못된 진입을 거르는 것이지 청산을 막는 것이 아니다.
청산은 리스크를 줄이는 방향이라 자동화 위험이 낮고, 오히려 지연이 더 위험하다.

## 2. 컴포넌트

### 2.1 공시 수집기
- DART / KIND를 주기적으로 폴링. 전종목 공시 수집
- **이중 타임스탬프 필수**: `published_at`(공시 게시) / `ingested_at`(시스템 인지)
- append-only. 수정·삭제 금지
- **백테스트 재생 기준은 `ingested_at`.** `published_at` 기준 재생은,
  실전에서는 수집 지연 때문에 절대 잡을 수 없었던 기회를 잡아버린다

### 2.2 시세 어댑터
- 엔진은 **1분봉만** 소비한다. 획득 경로는 어댑터 내부 구현
- 우선순위: 웹소켓 분봉(지원 시) → 틱 구독 후 로컬 집계 → REST 폴링
- **조회는 이 계층에서만 수행한다.** 전략이 직접 API를 호출하면 KIS 유량 제한에 걸린다

### 2.3 유니버스 빌더 (모멘텀)
- **매일** 전종목 모멘텀 점수를 산출해 순위 갱신
- **히스테리시스**: 편입은 상위 50위 이내, 이탈은 70위 밖. 경계 종목의 깜빡임 방지
- **워치리스트 일별 스냅샷을 append-only로 저장.**
  저장하지 않으면 백테스트에서 "그날의 워치리스트"를 재현할 수 없다.
  현재 코드로 재계산한 결과는 point-in-time이 아니다
- 워치리스트가 매일 바뀌어도 진입은 이벤트가 트리거하므로 회전율은 증가하지 않는다
- 보유 중 종목이 이탈해도 강제 청산하지 않는다 (진입 조건과 청산 조건의 분리)
- **역할 분담: 팩터 = 무엇을 살지, 이벤트 = 언제 살지**

### 2.4 전략
```
strategy(clock, data_view) -> 목표 포트폴리오 { 종목: (목표비중, 긴급도) }
```
- 주문이 아니라 **목표 상태**를 반환한다
- 엔진이 (목표 - 현재 포지션)을 계산해 주문 생성
  → 중복 주문이 원리적으로 불가능, 재시작 복구가 자명
- **긴급도(urgency)** 필드가 집행 비대칭을 표현한다: `IMMEDIATE`(청산) / `NEXT_OPEN`(진입)
- 팩터 전략과 이벤트 전략 모두 이 시그니처를 따른다. 추상화는 여기서 끝낸다

### 2.5 게이트
전략과 집행 사이에 강제 배치.

| 규칙 | 내용 |
|---|---|
| 최대 보유 종목 수 | 5 |
| 종목당 최대 비중 | 20% |
| 신호 경합 | 5종목이 차 있으면 신규 신호 스킵. 교체 없음 |
| 동일 이벤트 재진입 | 금지 (이벤트ID 기준) |
| 시간 기반 쿨다운 | 파라미터. 백테스트로 결정 |
| no-trade band | 목표 대비 편차가 임계치 미만이면 주문 생략 |
| 최소 주문금액 | 소액 계좌 부스러기 주문 방지 |
| 결제 제약 | D+2. 매도 대금 즉시 재사용 시 미수 발생 소지 |
| 장 운영시간 / 휴장일 | 확인 후 집행 |
| 킬 스위치 | 텔레그램 명령 |
| 승인 큐 | 진입에만 적용. 자동 전환 시 이 단계만 비활성화 |

### 2.6 집행기
- **멱등 키로 중복 주문 차단**
- 부분체결 처리. 체결 가중평균가를 진입가로 사용
- 프로세스 재시작 시 미체결 주문 복구
- API 타임아웃 시 "주문 접수 여부 불명" 상태를 명시적으로 다룬다
- 매 사이클 시작 시 **KIS 실제 잔고와 내부 포지션을 대조**하고, 불일치 시 매매 중단

## 3. LLM 판단 계층

### 3.1 역할과 호출 경계

- **진입 판단**: 공시가 모멘텀 신호인지 LLM이 판단
- **청산 조건 선택**: LLM은 **진입 시점에 청산 조건을 확정해서 출력**한다
- **판정은 규칙 엔진이 결정적으로 수행한다. 보유 중에 LLM을 재호출하지 않는다**

> 보유 기간 내내 재호출하면 캐시 키가 `(종목, 시각, 가격상태)`가 되어 캐시 히트가 사라지고,
> 백테스트를 돌릴 때마다 결과가 달라진다. 이벤트당 1회 호출로 고정하면
> `(이벤트ID, 프롬프트버전, 모델명)` 캐싱이 성립한다.

### 3.2 출력 스키마

```json
{
  "진입": true,
  "확신도": 0.0,
  "근거": "문자열",
  "청산조건": {
    "기술적": "사전 정의된 규칙 중 택1",
    "최대보유일": 30,
    "손절률": -0.05
  }
}
```

`기술적` 항목은 자유 서술이 아니라 **사전 정의된 규칙 집합에서 선택**한다.
자유 서술 청산은 코드로 판정할 수 없다.

### 3.3 프롬프트 관리
- 프롬프트는 버전 번호를 가진다. 변경 시 버전이 올라가고 캐시가 분리된다
- 사용자 가이드 추가는 프롬프트 버전 갱신으로 반영한다
- 모든 판단은 입력·출력·버전과 함께 로깅한다

### 3.4 근본적 한계 (완화만 가능)

과거 공시로 백테스트할 때 **모델이 해당 종목의 이후 주가를 이미 알고 있을 수 있다.**
학습 데이터에 포함되어 있기 때문이며, 가장 교묘한 형태의 look-ahead bias다.

- 완화: 프롬프트에서 회사명·종목코드·날짜 마스킹, 공시 본문만 제공
- 그럼에도 완전히 제거되지 않는다
- **따라서 LLM 전략의 백테스트 성과는 상한선으로 간주하고, 포워드 테스트를 우선한다**

## 4. 청산 규칙

기준가는 **진입 체결 가중평균가**. 스톱 레벨은 **절대 하향되지 않는다.**

| 구간 | 스톱 레벨 |
|---|---|
| 진입 ~ +5% 미만 | 진입가 −5% (고정) |
| +5% 도달 시점 | 진입가 (본전 이동) |
| 이후 | `max(진입가, 최고가 − k × ATR)` |

- 발동 시 **시장가 청산, 장중 즉시**
- 트레일링 판정은 **분봉 종가 기준.** 틱 저가로 판정하지 않는다 (장중 스파이크 노이즈 회피)
- 최대 보유기간 상한은 이와 무관하게 별도로 강제된다

### 4.1 갭하락 대응

갭하락은 제거할 수 없다. **방어는 포지션 사이징으로 흡수한다.**
종목당 20%이므로 한 종목 −15% 갭은 계좌 −3%에 해당한다.

- **유동성 필터**: 거래대금 하위 종목은 워치리스트에서 제외 (갭 크기와 슬리피지 모두에 영향)
- **백테스트에서 손절은 반드시 시가 체결로 시뮬레이션한다.** 지정가 체결로 모델링하면 결과가 거짓이 된다

### 4.2 실적 공시 취급

실적 공시를 **회피 대상이 아니라 이벤트 소스로** 취급한다. 사실상 PEAD 유형이다.

- 실적 공시는 장 마감 후 집중된다. 다음날 시가 진입 시 이미 갭이 반영된 가격이며,
  **시가 슬리피지를 반영하지 않으면 성과가 크게 부풀려진다**
- 동일 분기 실적이 잠정 → 확정으로 두 번 공시된다. **이벤트 정규화로 중복 진입 차단**

## 5. 백테스트 방법론

### 5.1 과최적화 방어 — 사전 확정 규칙

1. **기간 분리.** 학습 구간 / 검증 구간으로 분리하고,
   **검증 구간은 파라미터 확정 후 단 한 번만 확인한다.**
   검증 결과를 보고 파라미터를 수정하면 그 순간 검증 구간은 학습 구간이 된다
2. **최소 거래 표본 30건.** 미만이면 결과를 신뢰하지 않는다
3. **상대 기준.** 절대 수익률이 아니라 KOSPI 매수보유 대비 우위로 판단

위 세 규칙은 결과와 무관하게 사전 확정 사항이며 변경하지 않는다.

### 5.2 정합성 요건

- 재생 기준 시각은 `ingested_at`
- 거래비용: 위탁수수료 + 증권거래세(매도) + 슬리피지
- 상장폐지 종목 포함 (생존 편향 제거)
- 수정주가 처리 명시
- D+2 결제 제약 반영
- 워치리스트는 **저장된 일별 스냅샷**을 사용 (재계산 금지)

### 5.3 측정 지표

CAGR / 샤프 / MDD / 승률 / 손익비 / 평균 보유일 / 거래 횟수 / **총 거래비용 비중**

## 6. 운영 환경

### 6.1 역할 분리

| 위치 | 담당 |
|---|---|
| **로컬 PC** | 분봉 수집, 백테스트, 팩터 계산, 워치리스트 산출 |
| **클라우드 VM** | 장중 감시, 주문 집행, 청산 판정 |

무거운 작업을 VM에서 제외하므로 **1vCPU / 1GB 급으로 충분**하다.

### 6.2 VM 선택 기준
- **국내 리전 필수.** KIS 서버 지연이 손절 체결가에 직접 반영된다
- **무료 티어 사용 금지.** 예고 없는 인스턴스 회수·성능 제한이 발생한다.
  가용성이 곧 손실인 시스템에 적합하지 않다
- **상시 가동.** 스케줄 기동은 절감액 대비 기동 실패·상태 복구 실패 리스크가 크다

### 6.3 관리 인터페이스 — 텔레그램 봇

| 용도 | 수단 |
|---|---|
| 진입 승인 / 거부 | 인라인 버튼 |
| 체결·손절·장애 알림 | 푸시 |
| 킬 스위치 | 명령어 |
| 포지션·스톱 상태 조회 | 명령어 |
| 백테스트 결과 | 로컬 HTML 리포트 |

웹 대시보드를 채택하지 않는 이유: 승인은 모바일에서 즉시 이루어져야 하고,
**인터넷에 노출된 관리자 페이지는 계좌 조작이 가능한 공격면**이 된다.
인바운드 포트를 열지 않는 편이 안전하다. 필요해지면 이후 단계에서 추가한다.

### 6.4 가용성 리스크

청산이 자동이 되면서 **시스템 가용성 자체가 손실 원인**이다.
장중 루프가 죽으면 손절이 발동하지 않으며, 조용히 죽으면 인지조차 못 한다.

- 워치독 / 하트비트 기반 알림
- 재시작 시 포지션 및 트레일링 상태 복구
- 브로커측 스톱 주문을 백업으로 걸 수 있는지 확인 (KIS 지원 범위 확인 필요)

### 6.5 백업 — 재구성 원칙

| 데이터 | 원본 | 복구 방법 |
|---|---|---|
| 보유 포지션 | **KIS 계좌** (내 DB가 아님) | 잔고 조회로 복원 |
| 트레일링 상태(최고가) | 없음 — 파생 데이터 | 진입시각·진입가 + 분봉으로 **재계산** |
| 진입 체결 기록 | 내 시스템 | **백업 필요** |
| LLM 판단 결과 | 내 시스템 | **백업 필요** (재생성 불가, 비용 발생) |
| 이벤트·분봉·워치리스트 | 외부 / 재산출 가능 | 재수집 |

트레일링 상태는 백업 대상에서 제외할 수 있다. 진입 시각과 진입가만 있으면
이후 분봉의 최고가를 다시 구해 스톱 레벨을 정확히 복원할 수 있다.

**구체 방안**
- SQLite **WAL 모드 + 온라인 백업 API(`.backup`).** 실행 중 파일 복사는 손상 위험이 있다
- 체결·주문은 DB와 별개로 **append-only 텍스트 로그에도 기록** (DB 손상 시 최후 수단)
- 장 마감 후 오브젝트 스토리지로 자동 업로드, 버전 보관
- 부팅 시 KIS 잔고와 DB 포지션 자동 대조, 불일치 시 매매 중단 + 알림
- **분기 1회 복구 리허설.** 복구해본 적 없는 백업은 백업이 아니다
- 시크릿은 환경변수 + 파일 권한 제한. 소스 저장소 커밋 금지

---

## 7. 알려진 한계

- **과거 공시 아카이브가 제한적이면 이벤트 전략 백테스트 기간이 짧아진다.**
  초기에는 포워드 테스트(모의 집행 로그)를 병행한다
- KIS 모의투자에서 미지원 API가 있어 "모의 검증 후 실전"이 완전하지 않다
- 자본 1,000만원 기준 거래비용 비중이 크다. **회전율을 낮게 유지하는 것이 전략 성패보다 선행 조건**
- LLM 판단은 학습 데이터 오염으로 백테스트 성과가 과대평가될 수 있다 (3.4절)
