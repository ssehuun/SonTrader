## T1. 체결 후 포지션이 DB에 안 남아 영구 halt ✅ 완료 (3e71320)

### 증상

체결이 한 번이라도 일어나면 **다음 사이클부터 매매가 영구 중단**된다.

```
09:00  체결 → KIS 잔고에 포지션 생김
09:01  reconcile → DB positions는 비어 있음 → broker_only 불일치 → halt=True
```

2026-08-19 L6에서 수동 매수 3주로 같은 동작을 확인했다(그때는 안전장치가
정상 작동한 것으로 해석했는데, 실은 이 결함의 증상이었다).

### 원인

`data/positions.py`에 **`load_all()`만 있고 쓰는 함수가 없다.** 실전 경로
어디에서도 `positions` 테이블에 insert하지 않는다.

설계상 `reconcile`은 두 출처를 합친다 — KIS에서 수량·평균가, DB에서
`entered_at`·`exit_rule`·`event_id`. **DB 쪽 절반을 아무도 안 쓴다.**
그래서 `exit_rule`이 없어 청산 판정 자체가 불가능하다.

백테스트에는 `_apply_fills`가 있어 메모리 dict로 이 역할을 하는데, 실전에
대응물이 없다.

### 할 일

1. `data/positions.py`에 `upsert()` / `delete()` 추가
2. `apps/live.py`가 `engine/fills.py`의 판정 결과를 DB에 반영
   - 체결 확인 지점은 이미 있다: `broker_kis.resolve_unknown()`이 매 사이클
     `reconcile()` 첫 줄에서 호출되고, `UNKNOWN → FILLED` 해소와 `fills`
     기록까지 한다(2026-08-19 L6에서 실물 확인).
3. 청산 체결 시 `positions` 삭제 + `last_exit_at` 기록 (쿨다운 근거)

`engine/fills.py`(커밋 `0b20433`)가 판정 규칙을 이미 갖고 있다 —
**규칙을 새로 쓰지 말고 그걸 쓴다.** 백테스트와 갈라지면 안 된다.

### 완료 기준

- 체결 → 다음 사이클 `reconcile`이 `halt=False`
- `positions` 행에 `exit_rule_json`이 채워져 청산 판정이 동작
- 회귀: 백테스트 결과 불변

## T2. 미체결 주문이 "현재 상태"에 없어 중복 주문 🔴

### 증상

```
08:35:43  매수 5건 접수 (동시호가라 미체결)
08:39:16  같은 5종목 재주문 — 3건 접수, 2건 현금부족 거부
09:00     중복분까지 체결 (브이엠 62주 = 31×2, 피에스케이 30주 = 15×2 …)
```

### 원인

`reconcile`이 보는 브로커 잔고에는 **체결된 것만** 잡힌다. 미체결 주문이
"현재 상태"에서 빠지므로, 다음 사이클이 "아직 아무것도 없다"고 판단하고
같은 종목을 다시 산다.

**멱등 키로는 못 막는다.** 키에 사이클 시각이 들어가 다른 사이클이면 다른
키다 — 멱등 키는 "같은 사이클의 재전송"을 막지 "다음 사이클의 중복 진입"을
막지 않는다. 2026-08-19 L6에서 검증한 멱등성이 이 케이스를 커버하지 못했다.

### 남은 일 (절반은 됨)

커밋 `0b20433`에서 `Context.pending_order_symbols`와 `core/diff.py` 반영은
끝났다. **`engine/live_context.py`가 이 집합을 채우기만 하면 된다** —
`orders`에서 `status ∈ (submitted, unknown, partial)`인 종목코드.

백테스트는 즉시 체결이라 항상 빈 집합이다(변경 불필요).

### 완료 기준

- 주문 접수 → 미체결 상태에서 다음 사이클 → **재주문 없음**
- 매도도 막히는지 확인 (미체결 매도 중 재매도 시 잔고 부족 거부)

## 완료

### T1 — 체결 후 positions 기록 (커밋 3e71320)

`engine/reconcile.py`가 `resolve_unknown()` 직후 `_record_resolved_positions()`로
체결을 `positions`에 반영한다. 판정은 `engine/fills.py`가 하고 저장만 여기서 한다.
`orders.exit_rule_json`을 추가해 체결 시차가 있어도 청산 조건이 복원된다.

검증: 체결 → halt 없음 / 전량매도 → positions 삭제 / 부분매도 → 유지 /
exit_rule 없으면 기본값. 백테스트 회귀 CAGR -14.13% 불변.
